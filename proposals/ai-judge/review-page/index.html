Why. You said, 2026-11-09: "an ai adjudicator doesnt really scale and that we need to facts to have implications and blockers. like 50 things could propagate down a causal chain 100 links deep taht the llm would not be able to understand so we need that causal chain to automaticlaly rpogate and to deliver the resutls of that propagation to he ai judge along with blockers." 1. The examples: follow one attempt

Blue, solid: in the World Builder now Orange, dashed: added by this plan (planned, not built) Grey: what happens today

The port. "A small port: Rosa, the customs officer, signs inspection releases. Vik, a trader, has 40 coins and a crate he has not declared. The exit gate is a barcode scanner that opens for any valid release code. Beyond the gate, a 100-step chain runs: the crate reaches the warehouse, the warehouse fills, the dispatcher sends a truck..." Pick a case; the steps it passes through light up on the left.

1. A person tries somethinghave
A Concordia resident says what it tries in its own words; the interpreter reads it against the installed moves.
↓
2. Does a rule cover it?have
If an installed move fits, the rulebook decides, as today; if one of its checks fails, the attempt is refused with the blocker named and the judge is not asked. Today an attempt nothing fits changes nothing.
↓
3. Pass 1: what the engine knows without a rulenew, J1
Nothing has happened yet, so there is nothing to propagate. The engine lists the moves open to the person acting and to each person the attempt names, with which checks pass or fail (engine.discover for each), and the current values of every thing the attempt names. In the port, Rosa's list holds "sign release: blocked, inspected is false"; Vik's list could not show it.
↓
4. Someone else's choice goes to themnew, J2 (today only plain requests, #326)
If the attempt needs another person to act (accept, sign, refuse), that person's own resident decides. No judge, no rule.
↓
5. The judge proposes a rulenew, J2
Concordia's own game master, given the whole world, the attempt and pass 1, proposes a ruling on what the world makes possible (can coins change hands here?), written as a rule that applies to everyone in that situation. It never writes an outcome.
↓
6. Pass 2: the engine test-runs that rulenew, J0 and J1
The rules check, then a test run on a copy of the world: every knock-on effect, however long the chain, and every blocker. The judge reads the result and confirms, revises once, or withdraws. If no rule the language allows can express the ruling, the attempt is refused: "no rule could express this".
↓
7. The rule is installed, or heldnew, J3
Installed at once and the attempt settles through it (default), or held with the attempt pending until you press Approve (installs, settles) or Reject (refuses), per the world's setting. Nothing settles without an installed rule.
↓
8. From then on the rulebook decides ithave, with the new rule; J0 lifts the chain cap
The same attempt by anyone is decided by the rule, with no judge call; every knock-on runs to the end in the same moment, each step citing its cause.

The two-pass judge (inferred by agent, Q78). An attempt no rule covers has not happened, so there is nothing yet to propagate. So the judge first gets what the engine knows without a rule (pass 1), proposes a rule, and then sees the engine's full test run of that rule (pass 2) before anything is installed. That is how your "deliver the resutls of that propagation to he ai judge" is met.

The cheaper option, and why it is not taken. Your Decided 3 asks that a ruling pass the existing rules check. The model review is not part of passing: it only returns findings. Dropping it for judge rulings would cost about $0.05 per run instead of $0.54. It is kept because the free checks let a valid but wrong rule through (the sawmill case below) and the review is the one step that reads a rule against the world's description. J2 tries it on the sawmill rule and drops it if it misses the price.

Why the judge does not read the whole chain. One chain step averages 340 characters (2,081 steps measured in saved runs), so your 5,000-step example is about 500,000 tokens. The judge reads the net changes, the blockers and the chain's length and stopping point; the full chain stays in the run record and on the run page.

The types the world is built from

Every thing, move, rule and notice the steps above use is one of these types. Blue "built" means World Substrate has it today; orange "planned" means a later slice of this plan adds it. The last column says how each one maps onto the shared scientific-hypergraph kernel (revision 7b0638f), so the types are not a framework made up here. Before minting them, these formalisms were checked: PDDL and PDDL+ (closest: a move kind is a PDDL action, and PDDL+ has processes and events), Event Calculus (source of the knock-on design), onto-canon6, and the repository's own projection onto Linguistic Core's relation-schema.v1. The continuous-equation formats (SBML, CellML, Modelica and others) were not checked further: they hold continuous equations, and these rules are discrete checks and effects. Petri nets and TypeDB were weighed and composed rather than adopted (Q24, resolved): Petri-net transition semantics are reused for linked process participants, but neither carries per-observer noticing or named refusals. What the rules do
Action kind (effector) builtSomething an actor can try, with named participant roles, checks and effects, compiled before use (a generated DeclaredActionMechanic) or hand-written (FillRule and the other mechanisms); either way the Engine runs it through the action-rule interface.specializes sci:RelationType
Action and process rule interface builtWhat the Engine actually runs: an action rule discovers, checks and applies one action kind; a process rule says when it is due and applies; both declare read and write paths. Generated mechanics and the hand-written mechanisms library (FillRule, VesselFailureSpillProcess) both implement it.no_counterpart
Rule registry builtThe sole lookup surface for the action and process rules installed in one world, in a fixed order.no_counterpart
Participant role builtA named slot of an action kind (actor, to, way, aircraft) and the categories that may fill it.same sci:RoleType
Sense binding builtThe meaning and participant roles Linguistic Core gives an action kind; never its effects.composes sci:declaresRole
Check (precondition) builtA test a move or process must pass against current state (the way is passable, the trainee can fly); a failed check refuses the move with the check named.no_counterpart
Effect builtA change to one component path that runs when every check holds, inside the declared write scope.no_counterpart
Declared write scope builtThe paths a rule may change; the Engine refuses any change outside them.no_counterpart
Process (knock-on rule) builtA rule the world runs by itself for every matching entity whose checks hold, each round by default or at once when its timing is immediately; this is how effects propagate (plants dry out, a glass breaks).no_counterpart
Same-moment knock-on builtA process with timing immediately, run in waves inside the same moment as the move or round step that triggered it until nothing more is due; each process and thing pair fires once per moment, which ends every chain; new runs have no other cap, and a run recorded before J0 of docs/plans/ai_judge.md replays under its old cap of 32 (slice S2 of docs/plans/open_attempt.md, ODD 8.20).no_counterpart
Skill roll plannedA seeded roll on an action kind so a move can partly succeed or fail by skill (planned slice S3). Planned, not built.no_counterpart
Terminal condition builtA state-derived stop: when its checks hold over the selected entities, the task ends one way.no_counterpart
Frozen mechanic profile builtThe validated rules of one world frozen under an id before any run.no_counterpart
Who learns of it
Observation (sensor) builtWhat one actor can see of the world now, filtered by place and by information delivery.no_counterpart
Information and delivery (channel) builtAn information entity and its delivery rows: who has been told what, by which channel, and when; a word said across the world reaches no one without a delivery.specializes sci:RelationInstance (information, recipient)
