## Concrete task walkthrough

Starting state: saved run automatically playing. Intended completion: trace one action to its change, then inspect the same actor's pre-action information.

- Paused the saved run with the visible Pause button. This did pause, and the button became Play.
- The initial round-2 picture's list says Ari changed Technical condition to passing yes, previously no. That is a useful direct delta, but the stage and network do not hold the complete explanation together.
- At round 6, selected Recorded position of ari in the graph. The inspector shows `assent: true`, `stance: supportive`, `assent weight: 0`. The picture's delta says assent changed no→yes. This supports reading a local state change, not concluding why the entire pump remained inactive.
- Expanded round 3's knock-on effects. The visible receipt says validation passes (`r3-e00002`) caused by `r3-e00001`. The screen stayed on round 6. This is the first decisive tracing failure: selecting evidence of an earlier event does not restore its world state.
- Switched to Actor and chose Ari. Exact retained input can be opened, and includes the private sensor detail and public procedure. The action and world state vanish from the working view. Understanding the actor requires reading prompt/schema JSON and remembering the other screen.

This walkthrough diagnoses presentation and navigation only. It does not diagnose the simulation, rule validity, or cognition pipeline; full retained request/response trace analysis remains with the parent investigation.

## Recommended primary workflow and tradeoff

**Open saved run → understand its scenario and present outcome → select a round → select an attempted action → see actual before/after and refusal or knock-on effects → inspect that person's supplied information and exact evidence.** Start paused, or retain an obvious replay action after orientation. The timeline is the primary navigation; the selected transition and inspector are the main content. Show the complete world network on demand.

Router outputs are retained alongside this report:

- `saved-run-recommendation.json`: primary scroll-linked explainer; alternatives timeline, sequence diagram, staged explanatory machine. Choose **timeline** for repeatable seeking and revisiting evidence. A scroll narrative suits a fixed teaching story, but a saved run needs direct round access.
- `action-effect-recommendation.json`: primary **state-machine view**. Use a local transition with actual before/after and applied rule; do not invent a complete state machine from partial evidence. A staged explainer is an alternative for teaching a mechanism, less useful for arbitrary recorded-event inspection.
- `actor-input-recommendation.json`: primary **master-detail**. Person/round selection plus structured input detail preserves evidence and repeatable lookup. An answer card may help orientation but is insufficient as the evidence inspector.

Tradeoff: this reduces the prominence of an animated “world” and the all-world network. It improves the user's ability to verify cause and state at the cost of less ambient spectacle and one extra action to browse the whole model. The picture can remain when spatial location actually explains the event; this pump example does not visibly justify it as the front door.

Router gap: the generic catalog emits chat and training checks for this simple replay inspector. Those are marked not applicable, not reasons to add a chat or tutorial product. It also cannot establish that retained actor input is a person's belief; preserve that distinction in the source contract.

## Cognitive load and emotional journey

High extraneous cognitive load: six of eight checklist items fail for the critical trace task—single focus, chunking, hierarchy, one decision at a time, working-memory support, and purposeful progressive disclosure. Basic grouping and the small number of top-level mode choices are strengths. This is not principally a giant navigation-menu problem. Specific crowded decision/content areas: 8 simultaneously presented graph objects in the initial round-2 view; the exact actor input contains 19 offered-action entries in the retained round-1 context. These are measured counts from captured content, not claims of a universal four-item usability law.

The expected journey is curiosity → confusion during unsolicited motion → effort to pause → partial relief from a concrete delta → frustration when tracing requires another screen. This is a predicted emotional trajectory, not observed participant behavior. The end state clearly says the recording ended, but provides no similarly prominent explanation of the world outcome.

## Strengths to preserve

- Honest replay status: “nothing is being decided now” and explicit end-of-recording state prevent confusing replay with paid/live execution.
- Actual before/after values in “Changed this round” make real changes inspectable. Keep these prominent.
- Exact retained actor inputs are available, and focused network subsets reduce full-world clutter. Improve their presentation without hiding provenance.

## Persona risks and smaller observations

- First-timer: cannot identify the pump decision from the first headline; must decode names and action terms before understanding the task.
- Power user: cannot jump straight back to round 2 after finishing; historical receipts do not restore historical focus.
- Mobile reader: thought cards and object labels become a collision of text in a tiny stage. This is directly observed, not a predicted responsive bug.
- Two different “More” disclosures offer little prediction of destination. Native-looking select controls contrast with the custom buttons. These are secondary to the workflow failures.
- Rule refusal and words-not-matched are distinguishable in detailed text, but the single refused total and orange state need care: do not make the reader infer that every refusal was a rule decision.
